# WingedHorse 多 Agent 协作任务包

状态：执行基线 v1.0  
负责人：主 Agent 负责产品主线、接口契约、集成与最终验收

## 1. 协作原则

- 子任务只能在本文定义的范围内实施，不得自行增加一级导航、修改产品定位或更换视觉方向。
- 所有实现必须遵守仓库根目录 `AGENTS.md` 及产品、技术、UI、安全文档。
- 每个任务使用独立 `codex/<topic>` 分支；提交前保持变更聚焦，不混入构建产物和无关格式化。
- 子 Agent 提交的是候选实现，不代表功能完成；只有通过主 Agent 的契约、自动化、视觉和体验验收才可合并。

## 2. 主 Agent 保留任务

以下工作不可并行外包：

1. 单场景产品信息架构与核心体验循环。
2. Digital Life Engine 的领域边界、状态机和事件契约。
3. 问卷、人格、角色类型与养成状态之间的业务边界。
4. API、数据库和前端状态的最终数据契约。
5. 关键页面组合、分支集成、迁移策略和发布决策。
6. AI 安全、隐私边界与最终验收。

## 3. 可并行任务包

### WH-A01：竞品交互研究

目标：还原 Sowii/秃秃及 2–3 个陪伴养成产品的真实交互，而不是只总结功能。

交付：

- 首次启动、主页、角色互动、生活流、小纸条、拍照和限时玩法的逐步流程。
- 每一步说明触发方式、页面层级、返回路径、常驻导航数量和角色所占视觉权重。
- 可验证来源链接、截图日期和不能确认的部分。
- 输出 `docs/research/COMPETITOR_INTERACTION_AUDIT.md`，不得修改产品代码。

禁止：根据宣传文案臆测不存在的界面；建议照抄竞品视觉资产。

验收：能够回答“用户打开后第一眼看到什么、如何进入互动、如何返回生活现场、哪些能力没有永久入口”。

### WH-A02：视觉系统候选稿

目标：为“暖金绘本小镇”建立可实现的设计系统候选，不直接重做所有页面。

输入：`docs/UI_STYLE_GUIDE.md`、角色参考和主色 `#FFD057`。

交付：

- 390 × 844 的生活主页、生活记录层和互动 Sheet 三张高保真稿。
- 色彩、字体、间距、圆角、边线、阴影和动效 token 表。
- 正常、空、加载、错误、权限拒绝、减少动态状态。
- 资产清单：哪些必须由插画师/图像模型提供，哪些可由前端实现。

禁止：多 Tab 底栏、Emoji 作为正式物品、3D 塑料质感、描摹多邻国或现有 3D 参考图。

验收：角色是唯一视觉主角；不看颜色也能分清主次；交互入口不与角色竞争。

### WH-A03：问卷引擎 2.0

状态：等待用户提供新版题目和评分材料后启动。

目标：支持题库和评分规则持续变化，而不重写页面。

交付：

- 版本化 QuestionSet、Dimension、OptionEffect、ScoringPolicy 和 ResultMapping schema。
- 正向/反向题、多维权重、非计分题、条件题、并列处理和规则版本。
- 可达极值自动推导、配置校验、边界测试和迁移说明。
- 当前尚未发布，不保留旧问卷草稿或结果；上线后的新版本才按版本化迁移策略处理。

禁止：在 React 组件中计分；把尚未确认的业务阈值当科学常模。

验收：更换题目、权重或结果映射时，UI 与 API 契约无需修改。

### WH-A04：掉落游戏内核

目标：把现有演示升级为可测试、可结算的游戏内核；不负责最终插画。

交付：

- seeded RNG、掉落表版本、暂停/恢复、连击、难度曲线和结算摘要。
- 至少六类物品的领域定义、效果、稀有度、堆叠和消费条件。
- 触控、键盘、低性能及 `prefers-reduced-motion` 支持。
- Domain 单测及 Phaser/React 窄事件接口。

禁止：客户端直接成为奖励最终事实；用 Emoji 冒充正式交付资产；自行增加永久游戏导航。

验收：同一 seed 可复现；重复结算不重复发奖；暂停和异常退出行为明确。

### WH-A05：Digital Life Engine 领域层

目标：实现不依赖具体模型的生活事件模拟器。

交付：

- PetProfile、RelationshipState、DailyPlan、WorldContext、LifeEvent、LifePost、Interaction、MemoryCandidate 数据结构。
- 基于时间、状态、物品、历史事件和用户上下文的确定性规划接口。
- 去重复、冷却、因果引用、可见时间窗和事件状态转换测试。
- 模型仅负责表达/渲染，不得修改事实状态。

禁止：把定时生成几段随机文案称为数字生命；在领域层直接调用 OpenRouter。

验收：断开模型后仍可生成结构化生活计划；同一事实不会出现相互矛盾的动态。

### WH-A06：Agent 记忆与安全评测

目标：建立可重复运行的评测集，不修改核心产品交互。

交付：

- 人格一致性、记忆准确性、重复度、隐私泄漏、依赖诱导、高风险内容和模型降级测试集。
- 每项用例包含输入、必要上下文、允许行为、禁止行为和判定方式。
- 评测脚本与报告模板。

验收：测试不依赖某次随机措辞；失败能定位到安全、记忆、编排或模型层。

### WH-A07：持久化与账号基础

目标：让数据库成为核心业务数据的最终事实。

交付：

- PostgreSQL migration、Repository、事务与集成测试。
- 匿名游客 ID、后续账号合并的兼容结构。
- assessment、pet、inventory transaction、game session、life event、post、memory 和 consent 的基础表。
- 幂等、越权、删除和审计策略。

禁止：ORM 自动同步生产 schema；记录完整敏感对话或原始媒体。

验收：重启 API 后数据仍在；不同用户不可互读；重复请求不重复写入奖励。

### WH-A08：H5 与无障碍 QA

目标：建立当前版本和后续重构的可重复验收基线。

交付：

- 375、390、430、768、1440 视口截图与问题清单。
- 核心流程 Playwright 测试；键盘、焦点、触控、长文本、弱网、错误和减少动态测试。
- 严重度 P0/P1/P2 及可靠复现步骤。

禁止：只检查 CSS 类名或只报告自动化扫描结果。

验收：每个问题都有当前运行截图或可执行复现步骤。

### WH-A09：素材清点与角色生产需求

目标：筛选用户素材并形成正式 2D 角色生产清单。

交付：

- 文件名、尺寸、格式、用途、授权状态、是否相关、是否可直接使用。
- 八个形象的一致性差异和共用骨架可行性。
- 缺失视角、表情、动作、图层和小游戏精灵需求。

禁止：把下载目录内容视为自动可信；直接描摹 3D/AI 参考图。

验收：输出可交给插画师执行的图层命名、画板、锚点和动作列表。

## 4. 统一交付格式

每个子 Agent 必须在交付中包含：

1. 完成范围与未完成范围。
2. 变更文件清单。
3. 关键决策及理由。
4. 已运行的验证命令与结果。
5. 已知风险、假设和需要主 Agent 决策的事项。
6. 对应任务包验收标准逐项自检。

## 5. 主 Agent 四道验收门

1. **契约门**：领域模型、API、组件接口和产品定义一致。
2. **自动化门**：lint、typecheck、unit、build 和关键 E2E 通过。
3. **视觉门**：移动 H5 与桌面截图审查，状态完整，不使用临时资产冒充成品。
4. **体验门**：用户始终回到同一个角色生活现场，新增功能不把产品重新拆成工具导航。
