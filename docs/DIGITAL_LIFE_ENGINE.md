# Digital Life Engine v0.1

状态：P0 可运行基线 + 跨日叙事

## 目标

让数字生命在用户没有点击时仍按时间推进，并保证每条生活记录来自可追溯的结构化事实，而不是模型临时编造。

## 运行闭环

1. `WorldContext` 将 UTC 时间转换为用户本地日期与晨间、午后、晚间、深夜时段。
2. `DailyPlan` 根据角色类型、最低养成维度、关系阶段和稳定随机种子生成当天动机与三个计划时段。
3. `advanceDigitalLife` 在用户回访时惰性补算已经到点的计划，生成稳定 `eventKey`。
4. `LifeRepository` 使用访客凭证哈希隔离事件，并以 PostgreSQL 保存事件与每日计划；没有数据库时使用仅供开发的内存仓储。
5. Web 默认在本机运行同一领域引擎。只有用户开启“私密生活簿备份”后，才同步结构化事件与养成状态到 WingedHorse API。
6. Agent 只有在用户勾选“本次允许”后，才把结构化生活状态发送给 WingedHorse API，并由服务端领域事实直接回答；该上下文不会继续发送给 OpenRouter。
7. 相识第 1、3、7 天解锁固定故事章节；用户隔日回来会惰性补算，不要求连续签到。
8. 关系达到“熟悉伙伴”后，领域引擎偶尔安排一位确定性的 AI 牛马访客。访客不是真人、不会读取其他用户数据，也不构成公开社交。

## 幂等和真实性

- 计划 ID：`plan:{actor}:{local-date}`。
- 事件键：`{plan-id}:{date}:{hour}:{activity}`。
- 同一天、同一角色、同一动机的计划可复现。
- API、页面刷新和网络重试不会重复产生事件。
- OpenRouter 不得写入计划、背包、关系或生活事实。
- 用户行为事件和每日计划事件分别标记为 `user-action` 与 `daily-plan`。

## 当前活动池

- 补能：慢早餐、毯子午睡、看云、晚间阅读。
- 推进：整理补给、练习起飞、写纸条、地图散步。
- 减压：看云、午睡、写纸条、慢早餐。
- 探索：地图散步、练习起飞、整理补给、看云。
- 建立关系：写纸条、整理补给、晚间阅读、慢早餐。

活动是结构化事实，当前文字由审核过的本地模板渲染。后续可以增加插画或视频渲染器，但不得改变已经发生的事实。

## 数据和删除

| 数据         | 目的                     | 默认位置                     | 删除                             |
| ------------ | ------------------------ | ---------------------------- | -------------------------------- |
| DailyPlan    | 保持同一天行为一致       | 本机；用户开启备份后进入 API | 清除数据时同时请求删除服务端状态 |
| LifeEvent    | 展示私密生活簿和共同经历 | 同上                         | 同上                             |
| 随机访客凭证 | 隔离匿名用户数据         | 浏览器本机                   | 服务端确认删除后清除             |
| 访客凭证哈希 | 数据库归属键             | WingedHorse API              | 删除状态后不再保留业务记录       |

## 明确未完成

- 当前不是后台常驻进程，而是在用户访问时补算时间；规模扩大后再迁移到 BullMQ。
- 类型、养成值和背包仍有部分以客户端为事实源，不能用于付费经济或竞争排行。
- 还没有天气、地点、外部世界事件和可持续长期目标；当前故事弧只有三个经过审核的章节。
- 还没有账号与匿名访客合并。
- WingedHorse API 与 OpenRouter 分别授权：生活上下文默认不进入请求，用户可对当前会话主动开启服务端领域回答；OpenRouter 默认看不到结构化生活状态，深度模型个性化必须另行授权。
