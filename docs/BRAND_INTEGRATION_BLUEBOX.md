# 蓝盒子品牌合作接入方案

状态：交互与视觉方案已定，商业活动默认关闭；待品牌素材授权、优惠条款和可点击购买入口确认后实施。

## 1. 目标与原则

蓝盒子作为草原世界的“支持伙伴”出现，而不是打断用户的广告。合作需要同时满足：用户主动、来源透明、虚拟体验与购买解耦、可拒绝、可频控、可一键停用。

不做首屏广告、游戏中弹窗、自动打开购买页、购买后增强问卷结果、用数字生命劝购，或依据问卷、对话、生活事件、情绪、心率和视频信号定向。

## 2. 用户链路

1. 玩家尚未接到过时保证出现合作补给（可改成后续局概率）。游戏内只做演出、不出价/码，来来不说话：盒子略大于普通补给（约 1.2×），靠品牌蓝描边、静态柔光晕、「品牌合作」标签区分；入场光晕一闪后落为静态，不做持续脉冲。落点略偏角色，先慢后快约 0.55 秒；`prefers-reduced-motion` 下取消加速曲线，仍保留略大体积与静态光晕。稀有补给用金色微光+星屑，普通补给无光晕，三者效果分层。
2. 接住后结算页出现「合作补给」卡，主 CTA「领牛毛」；用户主动点击后才半屏展示商品与领取二维码（仿福利页，不自动弹）。领取二维码使用「牛马飞升进化群」福利码。
3. 用户在背包也可再次打开领取（主按钮「领牛毛」，次按钮给来来使用）。虚拟体验与领取相互独立。
4. 主动作`给飞马试试`消耗虚拟物品，提供轻量休息/能量反馈；无论是否购买都可完成。
5. 次动作`我想了解优惠`才展开真实产品、优惠、有效期、适用范围、履约/售后主体和外部入口；`先收好`随时关闭。
6. `不感兴趣`立即关闭本活动并进入 30 天冷却，不追问原因。

## 3. 频率与掉落策略

品牌物不能直接混入高频单物品权重表，否则每局大量掉落会放大曝光。使用局级活动判定：

- 默认在玩家**尚未接到过**该合作补给前，每局首颗必出一次（`firstRoundGuaranteed`，可关）。避免第一局漏接后永远不再出现。
- 接到并结算过后，后续局按 `laterRoundChance` 抽取，默认 0。
- 单局最多一个；活动结束或紧急停用后概率立即归零。
- 概率由活动配置控制，不由模型决定。

正式概率需结合小流量数据调整。优先观察反感/关闭/不感兴趣率，而不是只追求点击率。

## 4. UI 与素材

### 草原帐篷

- 将官方 Logo 放在帐篷原有挂牌位置，转译为暖白帆布缝制布标，保留蓝盒子蓝色识别。
- 布标不发光、不跳动、不附带价格、二维码或“点击购买”，不新增热区。
- 继续保留 WingedHorse 暖白、金黄、柔和蓝的场景体系；品牌蓝不扩散到导航和主按钮。

### 合作盒、掉落与领取

- 箱体使用深蓝纸盒轮廓，带小号「品牌合作」文本，不能只靠颜色区分。
- 当前活动池同时包含蓝盒子与 LiberLive；**每局最多掉落 1 个合作补给**，优先掉落尚未接到过的合作物。
- **掉落 / 背包列表身份图**：
  - 蓝盒子：`apps/web/public/brands/bluebox/logo.webp`（印字「蓝盒子® / BLUE BOX」）
  - LiberLive：`apps/web/public/brands/liberlive/logo.webp`（印字「LiberLive」）
- **领取半屏产品图**：
  - 蓝盒子：`pillow-n2.webp`（印字「蓝盒子 / BLUE BOX / N2」）
  - LiberLive：`product-aqua.webp` / `product-sun.webp`（机身印字「LiberLive」）
- **面向用户的品牌字样只取素材上已有的印字**：蓝盒子侧为 `蓝盒子`、`BLUE BOX`、`N2`；LiberLive 侧仅为 `LiberLive`。不自撰品名或营销句。产品侧固定用语（「品牌合作」「领牛毛」「牛毛」「与购买无关」）不属于品牌文案。
- 开盒 Sheet 使用现有圆角、间距和字体，不复制品牌电商页面。
- 已提供“加企微”图片含具体人员二维码，不得把个人身份码提交进公开仓库。结算/背包点击后展示活动配置中的领取码（牛毛福利）；游戏画布不出码。
- 帐篷场景挂牌**只露出蓝盒子**布标（暖白底 + 蓝方块 +「蓝盒子」），家园叠层帐篷与补给雨背景帐篷风格统一；LiberLive 仅进入补给掉落，不挂帐篷。

## 5. 技术设计

活动配置与普通物品定义分离，避免把购买地址或二维码硬编码进 `ItemDefinition`：

```ts
type SponsoredCampaign = {
  id: string;
  partnerId: string;
  enabled: boolean;
  startsAt: string;
  endsAt: string;
  dropPolicy: {
    minimumCompletedRounds: number;
    roundChance: number;
    maxPerRound: number;
    cooldownDays: number;
    dismissCooldownDays: number;
  };
  boxItemId: string;
  virtualRewardItemId: string;
  disclosure: string;
  productImage: string;
  logo: string;
  offer?: {
    title: string;
    description: string;
    destinationUrl: string;
    validUntil: string;
    terms: string;
    fulfillmentOwner: string;
  };
};
```

MVP 可使用经过构建校验且默认关闭的静态配置；上线活动改为服务端签名配置并设置紧急停用。外链必须过 HTTPS/Deep Link 白名单，不携带问卷、情绪、对话、匿名凭证或设备画像。

## 6. 数据与验收

仅记录匿名、最少必要事件：`sponsored_box_shown`、`caught`、`opened`、`offer_revealed`、`outbound_clicked`、`dismissed`。聚合报告至少同时查看曝光、接住、主动开盒、优惠展开、外链点击、不感兴趣和 7 日留存变化。

验收必须覆盖：首两局无品牌物、单局至多一个、频控跨刷新有效、拒绝冷却、活动过期/停用、重复结算幂等、无购买也可使用虚拟物品、外链白名单、键盘/触控与减少动态模式、390 px 和桌面视觉，以及无敏感字段进入事件或 URL。

## 7. 正式启用前待品牌确认

- 可点击的 HTTPS、微信小程序或 Deep Link；不能只有二维码。
- 优惠价格/折扣、有效期、库存、地区、适用条件和完整条款。
- 履约、付款、发货、退款、售后和客服主体。
- Logo 以帐篷缝制布标形式使用的书面授权，以及产品图/二维码公开范围。
- 企微二维码是否允许公开、联系人是否持续值守及失效后的替换机制。
- 活动开始/结束时间、初始概率和紧急下线负责人。

以上任一关键项未确认时，只保留帐篷合作视觉和关闭状态的技术预留，不开放掉落与购买。
