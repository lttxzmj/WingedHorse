# WingedHorse UI 与角色风格规范

状态：Baseline v0.4
视觉方向：原创 2D 矢量插画、温暖、幽默、有弹性、角色驱动

术语规则：产品内统一使用“草原”，不使用旧称。代码中已有的 `lawn-*` 仅为兼容性技术标识，不代表用户可见命名。

## 1. 参考风格如何使用

用户希望角色具有类似多邻国角色的 2D 插画亲和力。本项目只提取抽象方法：

- 轮廓清楚，缩小后仍能认出。
- 表情夸张，姿势能独立表达情绪。
- 色块简洁，阴影克制。
- 角色和产品反馈紧密结合。
- 动画短促、有弹性、可循环。

多邻国官方品牌指南强调角色需要通过有表现力的姿势清晰传达情绪或活动，这一方法适合作为表现力参考：

- https://design.duolingo.com/identity/imagery

### 原创性红线

- 不使用猫头鹰轮廓、Duo 的脸部比例、绿色品牌主色或其标志性姿势。
- 不描摹、多视图复刻或训练性复制多邻国现有角色资产。
- 不复刻其按钮尺寸、图标、课程路径、文案口吻或品牌字体组合。
- WingedHorse 必须通过“飞马/牛马混合身份、翅膀、鬃毛、工作与休养道具、暖金色”形成独立识别。

## 2. 品牌气质

关键词：

- 温暖，不甜腻
- 有梗，不嘲弄
- 活泼，不幼稚
- 柔软，但有行动感
- 情绪丰富，不病理化

对外名称：牛马飞升。口号：身在工位，心向草原。角色只叫来来。

视觉叙事：用户来到一片被暖光照亮的草原，一只略显笨拙但很有生命力的飞马来来在这里生活。它不是老师，也不是治疗师，而是会陪用户一起喘口气、接住小物品、慢慢长出翅膀的伙伴。

工位支架把手机屏幕当成来来的脸：全屏颜文字 + 一句短对白，不要成功学壁纸，不要堆口号。手机放到支架上（或点上工）即进入脸部模式；有人靠近时换成装忙小脸。下班生成四格漫画「来来的一天」：等宽竖条、左侧角色/颜文字、右侧短对白（几字），屏上预览与分享图同一结构。

### 场景地标

- 草原主场景必须具有“正在生活”的固定地标，当前以帐篷作为共同足迹入口，不再把角色孤立放在纯背景上。
- 草原主页采用“生活观察窗口”构图：角色是唯一前景主角，帐篷处于右后景，角色当下的一句话位于上方，今日行动条贴近场景底部；四者不得互相遮挡或使用同等视觉重量。
- 草原首页使用与补给雨同源的天空、远山和草地底景；帐篷作为独立右后景资产与生活簿入口，角色保持左中前景，不得把角色压在帐篷上。角色气泡贴在头部上方偏一侧、宽高随文案收缩，尖角指向嘴边，像角色正在说话；心情、元气与最多三枚可点击掉落补给作为低权重状态层出现。底部为「说一句」输入 +「接补给」；用户直接发送后，回复进角色对话框，点击对话框进入完整聊天详情，不得再并排上工/生活簿等同权图标。
- H5 顶部导航采用渐进响应：≤409 px（含 390 基准）身份独占首行，心情/元气与背包/设置落在下一整行工具条，保证在场文案可读；≥410 px 身份在左、状态与工具在右。心情与元气为「白底圆形图标 + 旁边状态文字」，背包与设置为纯白底圆图标（数量用角标）；密友入口只在设置内，不挤进顶栏；触控目标不小于 44 px，宽屏基准 48 px。
- 密友页对标一对一邀请（系统分享 / 复制链接），空态 + 一个主 CTA；列表只显示真实密友，不做编号空位，不本地假添加；收到 `?from=` 邀请码时可加入小圈。
- 草原角色尺度随视口宽高共同约束（`clamp` + `vw/dvh`），短屏不得因只跟宽度放大而压住底部输入条；气泡贴角色头部，掉落补给避开气泡区。
- 角色按钮获得键盘焦点时，焦点环只包围可见的“互动”提示，不得沿透明角色画布形成巨大矩形边框。
- 帐篷、补给雨入口和草原装饰使用同一套低饱和 2D 插画语言；交互热点叠加统一图标和文字，不用 Emoji 或单个汉字冒充图标。
- 共同足迹采用“旅行手账 + 拍立得”表达：省级地区只作为照片文字标签，未标地点的照片进入草原角落；不得按真实地理位置摆放标签，也不显示行政边界、街道、精确坐标或附近用户。
- 当前装饰底板只表达草原旅行氛围，不得包含中国地图轮廓或冒充地图。未来若确需地图能力，必须另行接入带审图号的标准地图或合规地图服务，并经过发布审核。

### 图标系统

- 产品功能图标统一采用 Lucide，默认 20 px、2.2 px 描边、圆角线性风格；同一操作在所有页面保持同一图标。
- Phaser 游戏物品使用 Lucide Static 官方 SVG，与 React 页面中的 Lucide 图标一一对应。
- 角色表情和场景插画不承担按钮图标职责；禁止在正式 UI 中混用 Emoji、中文字形、手绘 SVG 和多套线性图标。
- 图标按钮最小点击区域 44 × 44 px，纯图标控件必须有可访问名称。

### 游戏交互

- HUD 固定展示剩余时间、得分、接取数、连击和时间进度，不遮挡首个掉落物。
- H5 支持直接拖动角色与按住左右控制；按住控制使用 Pointer Capture，手指轻微移出按钮不应中断移动。
- 第一局在首次接取前展示短引导；接取后提供画面、分数、轻震动三层反馈，减少动态偏好开启时禁用非必要动效。

## 4. 字体

首发不依赖 Google Fonts 等境外字体服务。

推荐系统栈：

    -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif

字号令牌：

| Token   | 字号/行高 | 用途                       |
| ------- | --------- | -------------------------- |
| display | 36/44     | 结果类型、关键庆祝         |
| h1      | 28/36     | 页面标题                   |
| h2      | 22/30     | 区块标题                   |
| title   | 18/26     | 卡片标题                   |
| body    | 16/24     | 正文与选项                 |
| small   | 14/20     | 辅助说明                   |
| micro   | 12/18     | 声明、标签；不用于关键操作 |

- 中文正文默认 16 px。
- 标题使用 700–800 字重，正文使用 400–500。
- 避免长段居中；问卷题干可居中，选项文字左对齐。
- 结果页梗文案和安全/隐私文案必须形成明显不同的语气层级。

## 5. 布局与响应式

- 以 390 × 844 的手机视口为首要设计基准。
- 内容安全区：手机左右至少 20 px。
- 问卷主体最大宽度 640 px；桌面居中，不把选项拉满屏幕。
- 养成草原可以全宽沉浸，背包和设置使用受控内容宽度。
- 断点建议：480、768、1024、1280。
- 底部固定操作必须考虑 iOS safe-area-inset-bottom。

间距基于 4 px：

    4, 8, 12, 16, 20, 24, 32, 40, 48, 64

圆角：

- 小控件 12 px
- 选择卡与按钮 16 px
- 主卡片 24 px
- 胶囊仅用于标签、短筛选和状态，不把所有容器做成胶囊

## 6. 深度与线条

风格以扁平 2D 为主，通过少量深度帮助理解操作：

- 普通卡片：1 px 暖灰边线或非常轻的阴影，二选一。
- 主按钮：底部 3–4 px 深色承托，按下时整体下移并缩短承托。
- 弹层：中等柔和阴影，背景遮罩 32–40%。
- 插画阴影：单一光源，最多一层形体阴影和一层落地阴影。
- 不使用玻璃拟态、霓虹、复杂渐变或写实 3D 材质。

## 7. 基础组件

### Button

- Primary：brand-500 背景、ink-900 文字、最小高度 52 px。
- Secondary：surface-0 背景、ink-900 文字、line-100 边线。
- Tertiary：透明背景，用于低优先级操作。
- Destructive：只在确认动作中使用 danger 色。
- 必须覆盖 default、hover、active、focus、disabled、loading。
- 触控目标不小于 44 × 44 px，主操作建议 52 px 高。
- 点击交互：关闭系统蓝边与 `-webkit-tap-highlight`；指针点击不留 outline，仅键盘 `:focus-visible` 显示暖琥珀焦点环 + 浅金光晕。按下态用承托缩短与轻微下移，不用浏览器默认边框。

### QuestionOption

- 整卡可点，文字区域不得与装饰图标争抢注意力。
- 选中后同时使用描边、背景、图标三种反馈，不能只变颜色。
- 长选项允许自然换行，不截断。
- 选择后不自动瞬间跳题，给用户约 300–500 ms 的确认感或提供下一题按钮。

### Progress

- 显示完成比例和“第 n/17 题”，避免只用颜色。
- 进度变化使用 200–320 ms 动画。
- 不制造“答错”暗示。

### Card

- 同屏只保留一个最高视觉权重的主卡。
- 避免每一段内容都套独立卡片。
- 结果页卡片可导出，但页面中的操作区与导出内容分离。

### AI 伙伴对话

- 对话页是“私密陪伴空间”，不是客服表单或设置页：首屏依次呈现角色身份与在线状态、可收起的 AI 边界、当天对话、轻量输入栏。
- AI 身份与非医疗边界必须可见，但默认只显示一句摘要；完整说明采用可展开 `details`，不得占用首个角色回复的位置。
- 每条角色消息只保留角色名，不重复添加“AI ·”前缀；页面头部的 AI 标识与安全摘要承担身份披露。
- 文案人称：日常气泡用宠物旁白（「来来 / 它」），少用「我是来来」式自我介绍；按 8 种状态皮肤（含隐藏款天选）微调语调，不把类型名当角色名喊。
- 快捷开场在 H5 采用完整的 2 列按钮，禁止水平截断的胶囊列表；内容授权收纳于“本次发送范围”，默认仅发送当前对话。
- 用户未完成问卷时使用原创应用图标作为陪伴占位，不推断或伪造类型身份；完成问卷后再显示对应的原创 2D 角色资源。

### Dialog / Sheet

- 手机优先使用底部 Sheet，复杂设置使用全屏页面。
- 关闭按钮、返回手势和 Esc 均可恢复。
- 权限说明必须先解释用途，再触发系统权限弹窗。

### Feedback

- 成功：角色反应 + 简短文字，不只用绿色。
- 错误：就地说明原因与恢复方法，保留用户已输入内容。
- 空状态：说明为什么为空，并给出下一步。
- 加载：优先骨架或角色小动作；减少动态模式显示静态进度。

### 游戏 HUD 与养成互动层

- 游戏 HUD 只保留时间、得分、连击和暂停，固定在游戏画布上方，不与返回操作重叠。
- 倒计时和连击使用大字与短动效反馈；减少动态模式改为静态淡入，不使用持续缩放。
- 草原上的玩法入口表现为场景物件或角色气泡；同屏最多一个主事件按钮。
- 角色互动在手机使用底部 Sheet，桌面使用靠近角色的轻面板；必须可通过关闭按钮、Esc 和返回操作恢复。
- 物品效果使用文字与数值共同说明，不只依赖颜色、Emoji 或动画。

## 8. 角色设计圣经

### 8.1 角色基础

- 物种：版权申请稿确立的原创圆润牛马角色，保留“打工人”的笨拙感；“飞升”通过成长叙事表达，首版类型立绘不额外添加翅膀。
- 识别点：长方形口鼻、半垂眼、双角、短刘海、三角背鬃、梨形身体、小手、卷尾和心形脚。
- 比例建议：头颈约占整体高度 42–48%，身体呈圆角梨形，心形脚短而有节奏。
- 剪影必须在 64 px 高度仍能识别长口鼻、角、背鬃、梨形身体和卷尾。
- 眼睛负责注视与情绪，嘴和眉只做强化，避免靠文字解释表情。

### 8.2 绘制语言

- 使用闭合矢量形状和清晰色块。
- 主轮廓使用深棕或角色自身的深色，不使用纯黑。
- 同一角色同时出现的主色不超过 4 个，装饰色不超过 2 个。
- 形体阴影比底色深约 8–14% 明度，避免空气感渐变和塑料高光。
- 纹理只用于少量重点道具，不在角色身体铺噪点。
- 后续进化获得翅膀时，翅膀简化为 2–3 个大羽片，确保可绑定和可读。

### 8.5 八种类型静态立绘 v1

- 权威造型基准：用户提供的版权申请三视图与 8 种类型设定稿。
- Web 运行时资源：`apps/web/public/characters/types/*.webp`，统一 1024 × 1280 透明画布。
- 类型资源：chosen、saving、perpetual、overthinker、tired、veteran、explosive、mad-literature。
- 这些资源是静态合成立绘，用于结果页、草原与分享卡；不能冒充可动画分层源文件。
- 后续动画制作必须按 8.4 重新拆分/重绘图层，不直接对合成 WebP 做骨骼扭曲。

### 8.3 表情与动作

基础表情：

- neutral：自然呼吸和眨眼
- happy：嘴角上扬、耳朵抬起、身体轻弹
- proud：挺胸、翅膀张开、短暂停顿
- tired：身体略下沉、耳朵放松、眼睑降低
- comfort：靠近、点头或递出小物品
- curious：头部倾斜、眼睛追踪
- surprised：身体拉伸、翅膀快速打开
- resting：裹毯子、睡觉或坐下

禁止：

- 用黑眼圈、病号服、自残意象等表现用户低落。
- 让角色因用户未签到而哭泣、责备或威胁离开。
- 让“疯感”角色表现为危险、失控或污名化精神疾病。

### 8.4 分层交付

每个最终角色至少需要以下独立图层：

- head、body
- left/right ear
- left/right eye、pupil、eyelid
- muzzle、mouth、tongue 可选
- mane front/back
- left/right wing
- front legs、back legs
- tail
- shadow
- accessories

源文件要求：

- 首选 SVG、AI 或可编辑矢量源文件。
- 透明背景，标准正面/四分之三视角，统一画板与锚点。
- 同时交付色板、图层命名、表情表和使用授权。
- PNG/JPG 合成图不能作为可动画最终源文件。

## 9. 动效规范

动效目标是解释状态和增加生命力，不持续抢夺注意力。

时间令牌：

- instant：80 ms
- fast：140 ms
- normal：220 ms
- expressive：360 ms
- celebration：600–900 ms，最多一次

建议缓动：

- UI 进入：ease-out
- UI 退出：ease-in
- 角色反馈：轻量 spring，有一次回弹即可

规则：

- idle 动画每个循环 2–5 秒，加入随机眨眼避免机械同步。
- 用户操作反馈应在 100 ms 内开始。
- 同屏最多一个庆祝动效。
- prefers-reduced-motion 下移除位移、缩放和重复弹跳，保留颜色/静态帧反馈。
- Rive 状态机的公开输入由技术文档定义，设计不得随意改名。

## 10. 页面视觉结构

### 问卷

- 首屏：标题和一个明显的开测按钮优先；“长出翅膀”的传说使用小型羽毛、问号或星点埋钩子，不能以天马角色抢走开测注意力。
- 顶部：返回、当前剧情章节与简洁进度。
- 中部：题干和小型情境插画。
- 下部：纵向选项与下一步。
- 一屏尽量完整看到题干和至少 3 个选项；小屏允许页面自然滚动。
- 最终坦白局与计分题使用同一答题节奏，但用文案明确它不计分。
- 选择后使用不超过 expressive 令牌（360 ms）的单次确认与切题；减少动态模式不做位移或缩放，仅保留 80 ms 静态确认，并把焦点移到下一题标题。

### 结果页

- 第一视觉：类型名、一句判词和类型角色；首屏不得同时出现多个解释卡。
- 第二层：把四维、类型构成和行为白描收进一个连续内容面，使用分隔而非多张同权重卡片。
- 第三层：一条建议、飞升路线和一个圆形「开始摸鱼」主按钮。与主按钮同源：brand-500 暖金圆、brand-700 描边与承托、ink-900 标题；单层慢速光带 + 错开向心涟漪 + 轻呼吸光晕表达「被吸进摸鱼门」，文案保持静止。不使用宇宙黑洞 GIF。减少动态偏好时停用全部循环动效。
- 内容顺序参考成熟人格结果页的渐进展开方法：先确认“我是谁”，再解释“为什么”，最后给出“接下来做什么”；不复制竞品角色、文案和视觉资产。
- 分享卡不包含过多操作 UI。

所有页面同时遵守 `docs/H5_RESPONSIVE_CONSTRAINTS.md`；390 × 844 是视觉基线但不是唯一验收视口。

### 草原主页

- 角色占可视区域约 35–50%，是唯一视觉主角。
- 状态数值弱化为图标或短条，不做数据仪表盘。
- 对话气泡一次只显示 1–2 句。
- 任务、背包和小游戏由角色、场景物件或当前事件触发，不与角色争抢。
- 不使用四栏同权重底部导航，也不把主页做成多个功能卡片的门户。
- 默认底部区域只呈现当前情境所需的 1–3 个动作；没有动作时保持场景完整。
- 右上角只保留低权重的设置/隐私入口；问卷结果和角色档案收进设置或角色信息 Sheet。
- 当前实现以单一连续场景承载角色、回应与“今天的一件小事”，任务不得再拆成页面下方的第二张同权重卡片。
- 常用入口最多同时露出两个；其余入口进入角色互动 Sheet、生活簿上下文或页尾低权重链接。
- 状态只使用轻量半透明短条；禁止恢复粗黑描边、硬阴影、单字方框式“包/簿/设”入口。

### 生活记录层

- 从主场景上滑或点击相册、信箱等物件进入，使用连续过渡保留空间关系。
- 每屏突出一条角色生活事件，避免仿社交媒体的高密度无限卡片墙。
- 图片/视频是主体，文字保持短而具体；时间、地点和关联物品降级显示。
- 点赞、留言、送物品和保存记忆为内容内动作，不形成新的一级页面。
- 关闭或下滑后必须返回进入前的同一场景和角色状态。
- 信息流结构固定为“一条今日主故事 + 紧凑时间线”；只有最新事件使用大幅场景图，历史事件不重复铺同一张角色大图。

### 场景内互动

- 点击角色优先出现表情、注视和一句回应，再按需要展开轻量底部 Sheet。
- 不默认跳转到占满屏幕的通用聊天窗口。
- 小纸条、拍照、一起玩和说句话根据当前状态动态出现，最多一个主动作。
- Agent 响应等待时保持角色可见，通过倾听/思考状态反馈，不显示空白聊天页面。

### 掉落小游戏

- 掉落物使用形状、图标和颜色共同区分。
- 避免在动态背景上放小字。
- 暂停、分数和时间位于安全区域，不遮挡掉落路径。
- H5 在画布左右下角提供持续可见的 64 px 方向控制；桌面同时支持方向键与 A/D，拖动始终可用。
- 接住反馈同时显示物品名称、得分和持久化的已接数量；不能只依赖闪光或粒子。
- 碰撞反馈使用短缩放、粒子和音效；任何反馈都提供减少动态/静音替代。
- HUD 以画布内悬浮条呈现，使用柔和表面与轻阴影，不再以独立粗边框区块压缩游戏场景。
- 竖屏场景背景当前使用 `apps/web/public/game/prairie-drop-bg.webp` 原型生成资产，只用于环境，不含角色、物品、文字、Logo 或 UI；中央保持低信息密度，底部保留角色移动区。生产版权结论以 `docs/research/ASSET_INVENTORY.md` 的来源与授权台账为准，未补齐记录前不得宣称正式原创权利链完整。
- 草原主页和生活簿主故事可以复用同一环境资产维持世界一致性，但角色立绘必须继续使用权威类型资源，不得烘焙进背景。

### 品牌合作视觉

- 品牌标识服从 WingedHorse 场景语言：允许作为帐篷缝制布标、补给箱印记或物品来源标签出现，不使用广告横幅、悬浮角标、持续发光、脉冲或强制跳转。
- 帐篷上的合作 Logo 只作环境叙事，不承担购买按钮；现有场景入口和“共同足迹”交互不得与商业入口混合。
- 合作补给盒除颜色外还必须使用箱体轮廓和“品牌合作”文字区分；品牌蓝只用于合作物本身，不改写产品主色和全局组件。
- 开盒 Sheet 依次展示物品图、来源披露、虚拟用途与三个分层动作：`给飞马试试`、`我想了解优惠`、`先收好`。购买信息在第二次主动操作前不可见。
- 购买层必须保持原生 Sheet 排版，清楚区分主动作与安静的外链动作；不得使用伪系统提示、倒计时、划线虚价或诱导关闭。

## 11. 可访问性

- 默认达到 WCAG AA 等价对比度。
- 所有交互支持键盘焦点和可见 focus ring。
- 不以颜色作为唯一状态。
- 图片和角色动作提供有意义的 alt/aria 文本；纯装饰隐藏。
- 表单错误与对应字段关联。
- 支持 200% 文本缩放和长中文文案。
- 音频不是唯一信息通道。
- 视频/摄像头能力提供静态替代流程。

## 12. 视觉验收清单

- 灰度下仍能看出主次和可操作区域。
- 角色在 64 px、160 px、320 px 三档尺寸都清晰。
- 黄色按钮文字、辅助文字和禁用状态满足对比度。
- 390 px 宽度无横向滚动。
- 空、错、加载、禁用、焦点、选中、长文案均有设计。
